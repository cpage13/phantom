# Phantom: Project Context

Phantom is a general-purpose buffering HTTP upload sidecar. The service has zero upstream-specific knowledge; a thin upstream client adapts a specific target API onto Phantom's generic wire protocol.

Producers (or any HTTP client) POST a request chain to Phantom; Phantom acks fast with a synthetic 202 + `ChainResponse`, persists the body locally, and runs the actual upstream calls in the background with retries and token refresh. Three runtime properties matter:

- **Transparent on the wire.** Bytes Phantom forwards to upstream are byte-identical to what the agent sent. Dual SHA-256 hashes per `body_ref` (`body_hash` of raw bytes; `storage_hash` of stored encoded bytes) enforce this. The sender verifies both before forwarding and aborts to the `corrupted` terminal state on mismatch. This is byte identity of the BODY, not header identity: hop-by-hop, framing and connection-scoped headers (RFC 7230 section 6.1's set plus `Transfer-Encoding`, `Content-Length`, `Expect`, `Host`, and whatever `Connection` names) describe the hop Phantom terminated and are deliberately not forwarded. `Content-Encoding: aws-chunked` and `x-amz-decoded-content-length` ARE forwarded, because they describe the body bytes.
- **Always-encode.** One configured codec per deployment (default zstd). No size short-circuit, no `Content-Encoding` pass-through, no per-request opt-out. `PassthroughCodec` (storage token `"original"`) is an explicit operator choice for deployments that want zero codec overhead.
- **Crash-safe.** `asyncio.TaskGroup` at the composition root propagates an ordinary unhandled worker exception to the production CLI's fatal-worker bridge. The bridge asks uvicorn to drain and the pinned uvicorn runtime terminates by SIGTERM, so the orchestrator restarts. Persisted rows survive the restart. Startup recovery resets `attempting` rows to `queued`, quarantines any non-discarded row with a missing body to `corrupted`, and reconstructs one saturation charge for every persisted slot-holding row before workers start. TaskGroup's direct `SystemExit`/`KeyboardInterrupt` special cases are outside this ordinary-exception bridge contract.

## Naming (authoritative)

The naming convention is fixed by this table. CONTEXT.md is authority; any drift in code or docs is a defect.

| Concept | Name | Type |
|---|---|---|
| The chain's identity (= row's primary key) | `chain_id` | `UUID` |
| The credential cache axis | `uid` | `str` |
| Query grouping (admission stores the supplied value, else chain_id; every upload is a group of one) | `group_id` | `UUID` |
| Multi-file association (NULL means standalone) | `multifile_id` | `UUID`, nullable |
| Recorded position within a multi-file set (display only, never enforced at delivery) | `send_order` | `int` |
| Delivery stamp (set once on confirmed delivery, never moved) | `sent_at` | `datetime`, nullable |

The wire header for the credential cache axis is `X-Phantom-Uid`. The admin URL `PUT /v1/admin/tokens/{endpoint}/{uid}` carries `uid` as the cache axis path parameter. That is distinct from `GET /v1/admin/chains/{chain_id}`, which carries chain identity.

## Concept index

### Components

- **`phantom`** (the service; packaged as **`phantom-service`** because the bare name `phantom` is taken on PyPI; the import name stays `phantom`): generic buffering HTTP proxy. One Docker container per producer. Opaque at the HTTP layer; zero upstream-specific knowledge. Owns the wire protocol, every model, every header, every error code.
- **`phantom-client`**: universal Python SDK over the service's HTTP surface. Two runtime deps: `httpx`, `pydantic`. Built to be publishable to public PyPI.
- **`phantom-emulator`**: test emulator with generic upstream-shaped endpoints (`POST /v1/files/create`, `PUT /v1/files/upload/{token}`, OAuth2 token mint) plus controllable failure injection. It imitates a realistic upstream protocol shape without being tied to any one upstream.
- **`phantom-deploy`**: the Dockerfile and reference `docker-compose.yml` for container deployment (out of scope for the producer-side architecture).

### Auth & tokens

- **Token cache**: `dict[(endpoint, uid), Authorization]`. Persistent across Phantom restart. → [docs/adr/002-token-cache-keyed-by-endpoint-and-uid.md](docs/adr/002-token-cache-keyed-by-endpoint-and-uid.md), [docs/adr/003-persistent-token-cache.md](docs/adr/003-persistent-token-cache.md).
- **Endpoint**: upstream target identified by hostname (e.g., `files.upstream.example`). Primary axis of the `(endpoint, uid)` bearer cache key.
- **Credential identifier (`uid`)**: opaque caller-supplied string distinguishing identities at the same endpoint. Phantom never parses it. Avoid the aliases "user id" (too narrow; it also covers SP identities) and "token id" (suggests Phantom parses tokens, which it does not).
- **AD-mint capability**: when an instance's `ad_mint` config block is set (typed `AdMintConfig`), Phantom autonomously mints Azure AD client-credentials tokens via its own app registration and writes them to the (endpoint, uid) cache. When `ad_mint` is absent, Phantom waits for the client to push tokens via the `Authorization` header on ingress; that ingress caching applies ONLY to `phantom_bearer` routes, because they are the only routes whose egress reads a cached bearer. The (endpoint, uid) cache is the single source of truth for retry tokens either way.
- **`auth_expired`**: admin-visible state for a buffered upload whose cached token 401s without successful refresh. Also covers an `aws_sigv4` row whose signing credential is missing or rejected, woken by the `CredentialKicker` (the SigV4 analogue of `AuthKicker`) on a fresh credential push. Surfaces in the admin API so an operator can see "this is the only token/credential I have for this slot, and it's bad."
- **`auth_mode`**: per-route outbound-auth selector, `Literal["phantom_bearer", "none", "aws_sigv4"]` (`RouteCfg` in `config/settings.py` / the frozen `ResolvedRoute` in `routing/`). Picks bearer-inject (`phantom_bearer`) vs SigV4 re-sign (`aws_sigv4`) vs forward-as-is (`none`). Avoid the alias "auth type".
- **Destination credential / credential store (`signer_creds`)**: host-keyed store of `DestinationCredential` for the `aws_sigv4` mode. The key is `HostCredKey`, the destination host alone (no `uid`), deliberately distinct from the token cache's `(endpoint, uid)`. Persistent at rest (mirrors ADR-003); reads never carry secret material (ADR-004). → contrast [docs/adr/002-token-cache-keyed-by-endpoint-and-uid.md](docs/adr/002-token-cache-keyed-by-endpoint-and-uid.md), [docs/adr/033-service-based-sigv4-signing.md](docs/adr/033-service-based-sigv4-signing.md).
- **`SigningService`**: closed `StrEnum` of AWS services Phantom can SigV4-sign for; currently `S3 = "s3"`. REQUIRED on every destination credential; selects the botocore signer. Defined once in `models/credential.py`. Avoid the alias "signer type". → [docs/adr/033-service-based-sigv4-signing.md](docs/adr/033-service-based-sigv4-signing.md).
- **Re-signing (`aws_sigv4`)**: at egress the executor replaces the request's signature with a fresh SigV4 signature for the destination host, from the host-keyed destination credential (not the producer's). Body bytes are unchanged. The outbound header map is REBUILT from botocore's signed view, so no superseded casing of a rewritten header survives beside the fresh one; the cost is that every header botocore rewrites reaches the wire canonical-cased rather than in the casing the client sent, which is a visible narrowing of the transparent-on-the-wire promise for that one auth mode. An inbound presigned credential in the query is superseded material on this route and is stripped before signing. → [docs/adr/033-service-based-sigv4-signing.md](docs/adr/033-service-based-sigv4-signing.md).
- **`x-amz-content-sha256`**: the SHA-256 payload-hash header real S3 requires (the SHA-256 of the same unchanged body bytes). Avoid the alias "the body hash"; it collides with Phantom's own `body_hash` / `BodyHashes` field below. → [docs/adr/033-service-based-sigv4-signing.md](docs/adr/033-service-based-sigv4-signing.md).
- **`dest_host`**: the destination host a credential is keyed on (e.g. `s3.amazonaws.com`); the `{dest_host}` path segment of the admin push `PUT /v1/admin/credentials/{dest_host}` and the `sigv4_credentials[].dest_host` config key. Normalized lower-case via `_hostname`, so push/config key == forward-time lookup key by construction.
- **Raw-intake catch-all / fake-S3 intake**: the root-mounted `PUT|POST|PATCH /{phantom_path:path}` route (`routes/catch_all.py`) that accepts stock path-style S3 requests and synthesizes a one-step chain. The destination is `phantom_default_target` or a per-request `?phantom=<url>` carrier. Both carriers preserve the rest of the inbound query byte-for-byte, so query-addressed operations (`?partNumber=`, `?uploadId=`, `?uploads`, a presigned credential set) survive the rewrite; `phantom` is therefore a RESERVED query-parameter name, exactly as `X-Phantom-*` is a reserved header namespace. On an `aws_sigv4` route Phantom's own signature supersedes an inbound presigned credential, so the presigned parameter set is stripped before signing (ADR-033). The synthesized chain is template-inert (`templated: false`), because an object key may legally contain a `{{...}}` span. Distinct from the phantom-client `POST /v1/send` JSON-envelope ingress; re-signing (if any) happens at egress per the route's `auth_mode`, and ingress bearer caching is gated on that same `auth_mode`.

### Topology and storage

- **Instance**: a configured upstream-target within a Phantom process. One Phantom container hosts N instances; each has its own ID, storage partition, and optional `AdMintConfig`. Inbound requests are dispatched by target URL prefix to the matching instance; unmatched targets are rejected with 421. → [docs/adr/006-multi-instance-topology.md](docs/adr/006-multi-instance-topology.md).
- **Per-instance SQLite databases (deliberate split)**: `uploads.db` (the `uploads` + `idempotency_index` tables), `token_cache.db` (the persistent token cache), and `credential_store.db` (the persistent destination-credential store) sit side by side in `<data_dir>/<instance.data_dir>/`. The split keeps token and credential traffic off the hot uploads writer lock. → [docs/adr/030-two-database-design.md](docs/adr/030-two-database-design.md) (rationale, connection layout, the deliberate duplicate `token_cache` DDL in `schema.sql`), [docs/adr/029-read-only-admin-connection.md](docs/adr/029-read-only-admin-connection.md), [docs/adr/033-service-based-sigv4-signing.md](docs/adr/033-service-based-sigv4-signing.md).
- **`body_location`**: column on `uploads`; ENUM(`ram`, `file`). Records where a row's body bytes live. Single durability commit point, flipped only by the `PersistController`. Replaces the pre-Phase-1 `tier` column + `committed` flag.
- **`BodyStore`**: Protocol governing body storage. Three concrete bindings: `RamBodyStore` (RAM dict), `FileBodyStore` (disk via atomic rename, fsync of the file, of the chain directory, and of every directory level the store creates), `HybridBodyStore` (composes Ram + File; RAM-presence-authoritative reads). `Settings.body_store.mode` (`hybrid` / `all_ram` / `all_disk`) selects the binding at the composition root via the one shared `build_body_store` mode table (`runtime/startup_checks.py`). All three modes are first-class production modes. A mode flip over leftover disk state never refuses to boot: the guard backs the instance up and boots fresh, loudly (see Quarantine / backup below). → [docs/adr/025-never-refuse-to-boot-on-recoverable-config.md](docs/adr/025-never-refuse-to-boot-on-recoverable-config.md).
- **`PersistController`**: the SOLE writer of the `body_location='ram' → 'file'` transition. Migrates RAM bodies to disk on retry-linger (default 90 s) or RAM-pressure breach. Commit-last-column ordering: body files + parent dir fsync'd BEFORE the `UPDATE body_location='file'` commits.
- **Commit-last-column ordering**: the persist-handoff invariant. The flip of `body_location` to `'file'` is the durability commit point; everything that gives the file its persistent guarantees (write, fsync, parent-dir fsync) MUST run BEFORE the column UPDATE commits. Enforced three ways: code-review checklist + pre-commit grep (`scripts/check_persist_ordering.py`) + InvariantAuditor row walk.
- **`BodyOrphanJanitor`**: periodic worker that walks `FileBodyStore.list_orphans()` and deletes body files whose `chain_id` is absent from `uploads`. Closes C1 + invariant #4. Cadence configured via `body_store.body_orphan_sweep_seconds` (default 3600).
- **`RamPressureWatcher`**: periodic worker that polls `RamBodyStore.total_bytes()` against `body_store.ram_ceiling_bytes` and signals the `PersistController` when over ceiling (oldest body migrated first). Cadence via `body_store.ram_pressure_poll_seconds` (default 1.0). The ceiling is an enforced bound, not a best-effort gauge: a stalled attempt cannot pin RAM past it. → [docs/reliability.md](docs/reliability.md).
- **`InvariantAuditor`**: periodic row walk (Phase 3) that actively asserts invariants #1 and #3 from § 5 of `docs/architecture-intent.md`; bumps `invariant_violation_total` (labeled by invariant) on hits. Five more invariants are counter/gauge monitored; see the architecture-intent reliability-invariants tables.
- **`MetricsRegistry`**: in-process counter + gauge registry (`observability/metrics.py`). Surfaced via `GET /v1/admin/observability/counters` + `/gauges` + `/ram_pressure`. No external dependency.
- **Quarantine / backup**: the act of relocating an instance's live DB and body tree to recoverable, set-aside copies, driven by a `reason` discriminator (`storage/integrity.py`). The copies are flat stamped siblings in the instance data root, not a nested folder. Two paths produce them: the startup integrity gate (`reason=corrupted`, bumps `db_quarantine_total`) and the mode-flip guard (`reason=mode_switch`, bumps `mode_switch_backup_total`). A backup's identity is its uuid `backup_id`, recorded with both artifact paths in a manifest written before any artifact moves. Inventory is queryable via `GET /v1/admin/quarantine`; a chosen `mode_switch` backup is moved back by the one-call `POST /v1/admin/quarantine/restore` (clobber-safe, restart-required, never automatic on boot). → [docs/adr/025-never-refuse-to-boot-on-recoverable-config.md](docs/adr/025-never-refuse-to-boot-on-recoverable-config.md), [docs/adr/026-backup-identity-and-manifest-pair.md](docs/adr/026-backup-identity-and-manifest-pair.md); operator how-to in [docs/operator-playbook.md](docs/operator-playbook.md).
- **Transient-lock classifier**: `is_transient_lock_error(exc)` in `storage/sqlite_store.py`: the single shared rule for "this `sqlite3.OperationalError` is a ride-it-out `SQLITE_BUSY`/`SQLITE_LOCKED` contention, not a permanent fault." Deliberately narrow. Admission (→ clean `503 storage_unavailable`), recovery boot (→ bounded retry-with-backoff), and the sender's pre-claim and post-claim storage boundaries (→ wait one poll and continue) consult the one definition so they cannot drift. A post-claim row is already durably `attempting` and keeps its saturation slot; this handler does not requeue it, and startup recovery (or admin cancel/replay) reclaims it. → [docs/adr/023-transient-lock-classifier.md](docs/adr/023-transient-lock-classifier.md), [docs/adr/021-busy-timeout-tuning.md](docs/adr/021-busy-timeout-tuning.md), [docs/reliability.md](docs/reliability.md).
- **Persist linger**: retry-linger trigger for the `PersistController`. `body_store.linger_seconds` (default 90). A RAM body whose row has not reached a terminal state within this window migrates to disk.
- **RAM pressure**: ceiling-breach trigger for the `PersistController`. `body_store.ram_ceiling_bytes` (probe-filled when unset). When `ram_body_store_bytes > ram_ceiling_bytes`, the `RamPressureWatcher` signals the controller to migrate the oldest body.
- **Body size threshold**: size-aware persist bypass. `storage.persist_trigger.body_size_threshold_bytes` (probe-filled when unset). In hybrid mode, admission enqueues against the `PersistController` immediately (skipping linger) for bodies whose stored size is at or above the threshold. Pin to 0 to disable.
- **Reaper**: periodic coroutine that deletes terminal-state rows per the retention YAML. Iterates `succeeded`, `failed`, `cancelled`, `stored`, `corrupted`, `auth_expired`, `expired` on the same sweep.
- **Retention**: per-terminal-state, with metadata-vs-body retention separated. `RetentionCfg` carries a `<state>_metadata_seconds` and `<state>_body_seconds` pair for each terminal state.

### Request mechanics

- **Request chain**: Phantom accepts an envelope describing N HTTP steps with JSONPath capture from each response and `{{step.var}}` substitution into later steps; binary blobs ride as named `body_refs`. **Literal chain (`templated: false`)**: an envelope-level marker that turns substitution off for the whole chain, so a brace span in any field is content rather than a capture reference. It suppresses all six interpretation points (the parser's static placeholder pass at admission, the capture-TTL gate, and the four send-time substitution sites). The raw-intake catch-all sets it; a producer submitting literal chains may set it too. Defaults to `true`, so every authored chain is unchanged. → [docs/adr/009-request-chain-envelope.md](docs/adr/009-request-chain-envelope.md), [docs/adr/010-request-chain-envelope-schema.md](docs/adr/010-request-chain-envelope-schema.md).
- **Captured values**: response fields extracted per a step's `capture` directive (named JSONPath with optional `ttl_seconds`) and stored on the upload row. Used both for plumbing later steps and as the queryable record of upstream-assigned identifiers (like the upstream's real `file_id`) for the duration of retention.
- **Capture re-execution**: per-instance YAML knob controlling whether Phantom re-runs the producing step when its local capture-observation TTL elapses before later steps use the value. Default `false`. Reexecution occurs even when the producing step omits `idempotency_header`, which may create a duplicate. Enabling requires both an upstream-honored header for identity-safe replay and compatible capability renewal/lifetime; an exact cached response cannot revive an expired URL. → [docs/adr/009-request-chain-envelope.md](docs/adr/009-request-chain-envelope.md), [docs/adr/010-request-chain-envelope-schema.md](docs/adr/010-request-chain-envelope-schema.md), [docs/adr/011-capture-expiry-reexecution.md](docs/adr/011-capture-expiry-reexecution.md).
- **Local UUID**: a UUID the upstream client generates per upload, used as the synthetic `FileInformation.id` returned to the producer immediately (no wait for upstream reachability). Travels as `metadata.key_value_store["phantom_local_uuid"]` on the upstream request for forward-correlation.
- **Dual body hash**: every body_ref on every UploadRow carries `BodyHashes(body_hash, storage_hash)`. `body_hash` = SHA-256 of raw bytes; `storage_hash` = SHA-256 of stored encoded bytes. Sender verifies `storage_hash` before decode, `body_hash` after decode; mismatch transitions to `corrupted` (terminal). → [docs/adr/014-dual-body-hash.md](docs/adr/014-dual-body-hash.md).
- **Emulator upstream event oracle**: append-only typed `MetadataCreateEvent | BodyPutEvent` sequence used by E2Es to prove exact successful-response and accepted-side-effect cardinality and ordering. It records every successful create response (including idempotency cache hits) and every accepted PUT, but not rejected attempts; the separate `error_rate_5xx` oracle records only 503s generated by that configured branch, excluding `unavailable_until` and global pause. The emulator's established token-keyed maps remain latest-value views. Correlation is only a validated `phantom_local_uuid`; Authorization and arbitrary metadata are never copied. Upload tokens/URLs are synthetic emulator values used to prove keyed replay identity.

### Operational shape

- **Composition root**: `app.py`'s FastAPI `lifespan` (`phantom.app.create_app`) is the SOLE construction site for every long-lived coroutine. It supervises them under one `asyncio.TaskGroup`, runs the boot-time guards first (`runtime/startup_checks.py`), and is the one path production runs (`python -m phantom` → `create_app`). Spawn-site invariant: long-lived coroutines spawn only via the supervised TaskGroup; the unsupervised primitives are forbidden outside the lifespan's one sanctioned SIGHUP site, enforced greppably by the `forbid-asyncio-create-task-outside-composition` hook. An ordinary unhandled worker exception reaches the CLI fatal-worker bridge, which stops uvicorn through its signal path; the orchestrator restarts and persisted rows survive. → [docs/adr/024-app-lifespan-is-composition-root.md](docs/adr/024-app-lifespan-is-composition-root.md).
- **Hot reload**: operational config knobs (retention, saturation caps, codec choice, persist-trigger size threshold, capture re-execution, retry backoff strategy) reload via SIGHUP or `POST /v1/admin/reload`. Atomic snapshot swap via `SettingsHolder`. Worker count and the instance list still require restart; so do `server.*`, `ad_mint`, `phantom_default_target`, and `sigv4_credentials`. The per-instance route block (`routes`, `host_prefixes`, and the per-instance `data_dir`) is restart-required AND enforced: the boot `InstanceCfg` is frozen and every reader resolves that one snapshot, so a reload refuses a change to any of the three and logs a WARNING naming the instance and the drifted fields, on every reload until the process restarts. → [docs/adr/013-hot-reload.md](docs/adr/013-hot-reload.md).
- **State transitions are owned by the sender.** `workers/sender.py`'s `_on_*` handlers ARE the canonical state-transition table. The executor's discriminated-union result types are exhaustive by mypy. There is no separate state-machine module. → [docs/adr/015-state-transitions-owned-by-sender.md](docs/adr/015-state-transitions-owned-by-sender.md).
- **Smart defaults from system probe.** `config/probe.py` reads `psutil.virtual_memory().total`, `shutil.disk_usage(data_dir).free`, and `os.cpu_count()` at startup. `config/defaults.py` derives saturation, storage (including `body_store.ram_ceiling_bytes` and `persist_trigger.body_size_threshold_bytes`), and worker counts from those facts. Operator-supplied YAML values always win.

### Named code structures

- **`UploadRow`**: the persistence-side Pydantic model for one chain. Carries `chain_id`, `group_id`, `multifile_id`, `send_order`, `state`, `body_location` (Phase 1; replaces `tier`+`committed`), `body_hashes: dict[str, BodyHashes]`, `body_size_bytes`, `attempts`, `next_attempt_at`, `last_error`, `captured_values_json`, `received_at`, `sent_at`, `updated_at`, `body_discarded_at` (H4 carve-out).
- **`ChainAdminDetail`**: admin-only Pydantic model returned by `GET /v1/admin/chains/{chain_id}`. Includes `chain_id`, `state`, `body_location`, `last_step_completed`, `captured`, `attempts`, `last_error`. Distinct from the wire-facing `ChainResponse` (which is the ingress-time 202 body). Lives in both `phantom.models.admin` and `phantom_client.models.admin`; intentionally outside the byte-equality contract test (ADR-012).
- **`AdmissionResult`**: discriminated union returned by `SaturationGate.admit(declared_bytes)`. Variants: `AdmissionGranted`, `AdmissionRefusedSaturation`, `AdmissionRefusedDiskPressure`. The route dispatches via `isinstance`; the typed union forces an exhaustive match (mypy).
- **`AdmissionOutcome`**: return type of `routes/admission.admit_chain`. Carries `row: UploadRow` + `status_code: int` (202 for new admission, 200 for idempotency replay). The H7 closure makes `admit_chain` atomic: row INSERT + idempotency-claim INSERT in ONE SQLite transaction.
- **`ChainStepResult`**: discriminated union returned by `chain.executor.ChainExecutor.execute_one_step`. Variants include `Succeeded`, `Failed5xx`, `FailedAuth`, `BodyMissingError`, `CaptureExpiredRewind` (per ADR-011). Exhaustive by mypy; sender's `_on_*` handlers ARE the dispatch table (ADR-015).
- **`SettingsHolder`**: atomic-swap registry for the live `Settings` snapshot. `SettingsHolder.get()` returns the immutable snapshot; `SettingsHolder.replace(new)` swaps it atomically under the holder's lock. Workers consult via `InstanceContext.current_settings()`.
- **`InstanceSettingsSnapshot`**: the per-instance immutable view of the live `Settings` (one snapshot per instance, swapped atomically on reload). Workers read on each tick; never mutate.
- **`BodyHashes`**: frozen dataclass `(body_hash: str, storage_hash: str)`. SHA-256 hex digests of raw bytes (`body_hash`) and stored encoded bytes (`storage_hash`). Per-`body_ref`, persisted as JSON in `UploadRow.body_hashes`. See ADR-014.
- **`MachineFacts`**: frozen dataclass holding the result of `probe_machine()`. Inputs to `compute_defaults()` → `ResolvedDefaults`.
- **`ResolvedDefaults`**: frozen dataclass with every probe-derived knob (`max_in_flight`, `max_in_flight_bytes`, `max_disk_bytes`, `large_body_threshold_bytes`, `max_large_in_flight`, `ram_ceiling_bytes`, `body_size_threshold_bytes`, `worker_count`).

### Cross-implementation (ADR-035)

- **Primary implementation**: the Python service is the permanent reference; every change lands and hardens there first, then is applied to the trailing **Go port** (phantom-service only). Avoid the alias "rewrite"; Python is not being replaced. -> [docs/adr/035-python-primary-trailing-go-port.md](docs/adr/035-python-primary-trailing-go-port.md).
- **Contracts artifacts (`contracts/`)**: the committed language-neutral wire/admin/config contracts, GENERATED from the Python models by `scripts/export_contracts.py` and drift-gated in CI. Never hand-edited.
- **Conformance suite**: the `conformance`-marked e2e modules (implementation-blind assertions only) driven through the subprocess harness's `E2E_SERVICE_CMD` seam. The port's acceptance gate: `E2E_SERVICE_CMD=<binary> pytest -m conformance`.
- **Implementation identity**: `GET /v1/admin/status` reports `implementation` + `service_version`, so operators can tell which binary answered.

## Captured-values redaction

`ChainCapture.sensitive: bool` is the wire-visible structural mechanism for marking a captured value as containing credential-grade data. The upstream `upload_url` (presigned PUT, 7-day TTL) is `sensitive=True`; `file_information` is not.

Redaction contract:

- **Log output**: the `SensitiveCaptureRedactor` log filter (in `phantom.observability.logging`) inspects records for `captures` and `sensitive_captures` extras; values marked sensitive are redacted in-place to `<redacted>` before the formatter sees them. The executor emits captures at DEBUG level only and gates the `extra=...` construction behind `logger.isEnabledFor(logging.DEBUG)` so production INFO deployments pay zero cost. This holds for EVERY configured sink, the `observability.log_to_file` sink included: both filters are attached per handler rather than to the logger, and the no-sink case installs a `NullHandler` so there is never an unfiltered `logging.lastResort` fallback channel.
- **Admin responses**: loopback only (per [docs/adr/004-admin-api-loopback-no-auth.md](docs/adr/004-admin-api-loopback-no-auth.md)). Admin responses surface the raw captured value; redaction is log-only. The justification is that admin callers are by construction on-host operators; the `sensitive` flag controls log-channel behavior, not the persisted record.

## Permitted `Any` sites

The `Any` type is a last resort. mypy strict mode is the target. Every use of `Any` in `src/*/src/` must fall into one of the categories below; new code MUST justify any addition by adding an entry here.

The permitted patterns:

1. **`dict[str, Any]` for genuinely dynamic JSON payloads**: JSON bodies whose shape is determined by the chain's upstream (`ChainBodyJson.value`, captured values, JSONPath extraction targets, FastAPI request/response JSON envelopes, the chain envelope's free-form metadata, AD-mint token endpoints' return shape). This also covers pydantic before-validators that take the raw pre-validation input (`data: Any`, e.g. `_default_idempotency_key` in both `models/chain.py` copies) and local `Any` bindings for `json.loads` results. The Pydantic v2 ecosystem itself uses this pattern at every dynamic-content boundary. The Pydantic field's `description=` carries the semantic contract; the type carries the structural reality.
2. **`Any` for SQLite parameter binding**: `sqlite3` accepts heterogenous parameter sequences and DB-API drivers (aiosqlite included) type the parameter slot as `Any` upstream. `storage/sqlite_store.py` uses this for `_params_for_insert` (line 395) and its `params: list[Any]` query-binding lists.

The specific bare-`Any` signature sites:

1. **`src/phantom-service/src/phantom/chain/jsonpath.py:41,71`**: `extract(body: Any, path: str) -> Any` and `substitute(template: str, values: dict[str, dict[str, Any]])`. JSONPath operates on arbitrary JSON; its input and output are constrained only by JSON validity. Specifying a constrained type would lie about the contract.
2. **`src/phantom-service/src/phantom/chain/parser.py:98`**: `_walk_json_for_placeholders(value: Any)`. Walks an arbitrary JSON tree looking for `{{...}}` template placeholders. Same justification as JSONPath.
3. **`src/phantom-service/src/phantom/runtime/reload.py:175`**: `__exit__(self, exc_type: Any, exc: Any, tb: Any)`. The context-manager protocol's `__exit__` signature is fixed by CPython; library users idiomatically type it `Any` to match the upstream protocol.
4. **`src/phantom-service/src/phantom/routes/admin.py`**, the `_request: Any  # FastAPI Request` pattern (ten admin handlers; grep `_request: Any`). The FastAPI `Request` type is a heavyweight starlette import; the parameter is unused in the handler bodies and exists only to satisfy FastAPI's injection signature.
5. **`src/phantom-emulator/src/phantom_emulator/routers/upstream.py:294`**: `_scope_for_policy_lookup(_token: str) -> Any`. The failure-injection scope-key type is determined at runtime by the `FailurePolicy` cache; the lookup interface is opaque by design.

The `dict[str, Any]` pattern at JSON boundaries is not enumerated above because it is the idiomatic pattern at JSON boundaries and counting every usage would obscure the actual bare-`Any` surface. If a future module replaces one of the bare-`Any` sites with a constrained type, this list shrinks.

## Pilot surface area

A minimum-viable pilot configuration exercises the smallest end-to-end Phantom deployment. The pilot's load-bearing surface:

- **Ingress**: `POST /v1/send` with a two-step chain envelope (`create_file` metadata POST + `put_s3` body PUT) and a `body_refs={"body": <bytes>}` multipart submission. Authorization is producer-supplied (Bearer) on the request; Phantom caches it under `(endpoint=files.upstream.example, uid=<JWT sub>)`.
- **Admin (loopback)**: `GET /v1/admin/chains/{chain_id}` returns `ChainAdminDetail` (state, body_location, captured values, attempts, last_error); `GET /v1/admin/tokens` lists cached token slot status (no bearer values surfaced); `GET /v1/admin/status` echoes resolved-default summary and observed machine facts; `POST /v1/admin/reload` triggers a hot reload from YAML.
- **Retention**: succeeded metadata kept for 3 minutes (default) so the captured upstream `file_id` is queryable post-delivery; succeeded bodies dropped on success.
- **Failure modes covered by the pilot's test surface**: 5xx retry on metadata or S3 step, 401 retry with auth_expired → AuthKicker wake, Phantom capture-observation TTL elapsed, producer restart, Phantom container crash mid-`persist_now`, saturation cap. Actual upstream capability expiry is a distinct clock and is not synonymous with Phantom's observation TTL.

Out of pilot scope: admin authentication (loopback bind IS the auth), GET-side proxying for downstream non-upload traffic, multi-routing across heterogeneous upstreams in a single instance.

## Conventions

- **Nothing is locked by labeling.** Decisions are settled when they survive against every deployment they need to serve. ADRs record settled-pending-validation decisions; the right to revisit them stays open.
- **Phantom's scope is POST/upload buffering only.** GET-side proxying for downstream traffic is not part of Phantom. Admin endpoints under `/v1/admin/` use GET for read operations (status, chain lookup, body retrieval); these are loopback-only and distinct from the producer-side POST ingress that Phantom buffers.
- **Coding standards** (Python 3.14+): full type annotations, `from __future__ import annotations`, `pydantic.BaseModel` at serialization boundaries (every field carries a non-empty `Field(description=...)`), `@dataclass` (or `@dataclass(frozen=True)` for internal data with no reassignment requirement) for internal structured data, `logging.getLogger(__name__)` for operational output (no `print()`), no bare numeric literals in production code.
