# 013. Hot reload of operational config via SIGHUP and admin endpoint

Operational config knobs reload via SIGHUP or `POST /v1/admin/reload`. The reload is an atomic swap of an immutable `InstanceSettingsSnapshot` through a process-wide `SettingsHolder`, plus three reload-time pushes for state workers do not re-derive per use: the per-instance `cfg` repoint, the retry-strategy rebuild, and the saturation-gate cap update. The distribution architecture (which mechanism a knob may use, and why) is ADR-031; THE TABLE BELOW IS THE CONTRACT, mirrored and enforced by the knob-matrix contract test (`src/phantom-service/tests/unit/test_reload_knob_matrix.py`). Verified live by `tests/e2e/test_hot_reload.py`.

Mechanisms (ADR-031): **live-read** = the consumer reads the live snapshot at every point of use (the canonical mechanism); **push** / **rebuild** = applied once by `apply_reload` (enumerated exceptions); **restart** = deliberately not reloadable. Read the table PER ROW, never per YAML namespace: one namespace can mix mechanisms (notably `body_store.*`, whose tuning rows are live-read while `body_store.mode` is restart-required) (C6 legibility note 2026-06-12).

Mechanism:

`Settings.reload_from_yaml(path)` is the load classmethod, called with the host probe ON (the default). Probe-fillable knobs the YAML omits re-resolve from current machine facts exactly as at boot, so the smart-defaults deployment posture (omit the capacity knobs, trust the probe) survives reload; operator-pinned YAML values always win. (R7-1 reconciliation: the original `skip_probe=True` fast path reloaded a probe-reliant YAML into `None` holes that swapped live before validation could refuse, half-applying the reload and silently disabling RAM-ceiling enforcement; the probe is three cheap syscalls and reloads are rare operator actions, so the skip bought nothing worth that.) Resolution and validation complete inside the classmethod BEFORE any snapshot swap. Every reload failure - parse (`yaml.YAMLError`), validation (`pydantic.ValidationError`), and file-read failures (`OSError` for a vanished file, `UnicodeDecodeError` for a non-UTF-8 byte; R8-2) - belongs to the one shared `RELOAD_FAILURE_ERRORS` set consumed by BOTH postures: 422 envelope on the admin endpoint, log-and-keep-previous on SIGHUP. In every case the in-flight `SettingsHolder` is not swapped, so the running config is unaffected. The admin endpoint returns 404 when hot reload is disabled (composition root constructed `create_app` without a `settings_path`).
